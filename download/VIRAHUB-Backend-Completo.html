📄lib/server/hash.ts~44 líneas

Hashing y normalización. Sin dependencias externas.

  • fnv1a(input: string): string — FNV-1a 32-bit, devuelve 8 hex chars. Usa Math.imul para precisión 32-bit.
  • fnv1a64(input: string): string — Concatena dos FNV-1a 32-bit con seeds distintos ('a:' y 'b:'). Devuelve 16 hex chars.
  • normalizeText(text: string): string — Lowercase, strip URLs/handles/hashtags/emojis, collapse whitespace.
  • cuid(prefix = 'c'): string — ID tipo cuid con timestamp base36 + random + counter.

Scoring — fórmula completa

Time-decay: Weight(t) = e^(-λ·Δt), λ = ln(2)/6 ≈ 0.1155 por hora. Half-life = 6h. Una mención de hace 24h pesa 6.25% de una nueva.

Velocity real: velocity = menciones_últimos_15min / 15 (menciones/minuto en ventana 15min)

Acceleration: acceleration = velocity(15min) - velocity(60min). accelerationRatio = velocity(15min) / velocity(60min)

Score ponderado:

score = (0.30 × velocityScore +      // min(1, velocity/5)
         0.25 × accelerationScore +   // bucketed por ratio: ≥2→1.0, ≥1→0.5-1.0, ≥0.5→0.2-0.5, <0.5→ratio×0.4
         0.15 × spreadScore +         // min(1, sourcesRecent60.size / 3)
         0.08 × entropyScore +        // Shannon entropy de sources en últimos 15min
         0.10 × authorDiversityScore +// min(1, uniqueAuthors60 / mentionsLast60)
         0.07 × freshnessScore +      // weightedVolume / mentions.length
         0.05 × trust                 // avg SOURCE_TRUST per source
        ) × (1 - trashPenalty) × 100

Time-decay del score: 0 menc en 30min → score ≤ 5. 0 menc en 60min → score = 0.

Gates: score ≥ 50 requiere menc15 ≥ 2 AND sources60 ≥ 2. Score ≥ 70 requiere accelerationRatio ≥ 1.5 AND sources60 ≥ 3.

Source quota: Si fuente dominante >35% sin corroboración social (X/Reddit/Bluesky) → penaliza proporcionalmente.

Single-mention: score capado a 15.

Shape + Phase detection

function detectShapeFromAcceleration(acceleration, accelerationRatio, samples): Shape
// accel: ratio ≥2 o nuevo cluster con accel >0
// rise: accel >0.05 AND ratio ≥1.2
// decay: accel <-0.05 OR ratio <0.5
// wobble: alta varianza sin accel clara
// flat: resto

function detectPhaseEarly(velocity, acceleration, menc15, menc60, src15, shape, ageHours): Phase
// rising: age <2h AND menc15 ≥2 AND accel >0 AND src15 ≥2
// peaked: velocity >0.3 AND menc60 ≥5 AND shape ≠ decay
// decaying: shape = decay OR menc15 = 0
// forming: resto

Scraper Local de X (scripts/local-x-scraper/)

🔧scripts/local-x-scraper/scraper.js~234 líneas · Node.js + Playwright

Arquitectura híbrida: tu PC scrapea X con Playwright (pasa JS challenge), envía tweets a Vercel via POST /api/v1/ingest, aparecen en dashboard en <5s.

Config (env vars)

VERCEL_URL="https://terminal-de-viralidad.vercel.app"
VIRAHUB_INGEST_API_KEY="virahub-local-2025"
SCRAP_INTERVAL="60000" // 60s

Flujo

  1. getReactiveQueries() — lee trends de Vercel (GET /api/v1/trends), extrae keywords de títulos
  2. Combina con FIXED_QUERIES (5 términos: AI, crypto, OpenAI, GPU, regulation)
  3. searchX(browser, query) — abre Playwright en xcancel.com/search?q=..., espera .tweet-content, extrae tweets via page.evaluate
  4. Dedup por externalId
  5. sendToVercel(tweets) — POST /api/v1/ingest con { apiKey, mentions }
  6. Resultados aparecen en dashboard via SSE

Uso

cd scripts/local-x-scraper
npm install && npx playwright install chromium
node scraper.js           # modo continuo
node scraper.js --once     # una sola vez

Bugs Conocidos y Observaciones

Bug 1: ingestMentions inicializa newClusters = 0 pero nunca lo incrementa. Siempre devuelve 0.

Bug 2: getActiveAuthorsAsSeeds() en x-adapter.ts es un no-op (cuerpo vacío, solo comentarios). Siempre devuelve [].

Bug 3: WATCHLIST está duplicada en config/sources.ts (6 subreddits) y ingest/adapters.ts (5 subreddits). Los adapters usan la local.

Bug 4: scraper.js usa contentHash: '${t.id}' (raw ID, no hash real). Funciona pero rompe el contrato FNV-1a.

Bug 5: 5 de 11 eventos SSE no son consumidos por ningún hook específico (velocity_spike, phase_changed, log_appended, alert.triggered, alert.acknowledged, report.updated).

Bug 6: live toggle en el provider es cosmético — no pausa SSE ni REST polling.

Bug 7: /api/v1/reports traga range inválido silenciosamente (fallback a '6H') en vez de devolver 400.

Bug 8: /api/v1/trends declara cursor pero nextCursor siempre es null. Paginación no implementada.

Bug 9: /api/v1/engines/:id/logs parsea limit y level pero los ignora — siempre devuelve 1 log sintético.

Bug 10: /api/v1/trends/:id parsea range pero no lo usa.
